Spring Boot 개발자가 Unsik React 화면을 이해하기 위한 문서

이 문서는 프론트를 처음 시작하는 백엔드 개발자가 현재 구현된 로그인, 그룹, 투표, 식당 추천 화면을 읽고, 수정하고, 다음 기능을 붙일 수 있도록 만든 학습용 가이드입니다. 용어를 외우기보다 브라우저에서 어떤 파일이 어떤 순서로 실행되는지 이해하는 데 초점을 둡니다.

현재 앱 /main, /grouplist, /groups/:groupId/votes
프레임워크 React 19 + React DOM
빌드 도구 Vite
언어 TypeScript strict
React TypeScript CSS Vite npm SPA

1. 현재 만든 것

지금 저장소는 React 웹 프론트엔드입니다. 네이티브 앱이나 Expo가 아니라, 브라우저에서 열리는 웹 앱입니다. 현재는 /main 메인 화면, /auth/kakao/callback 카카오 인증 콜백 화면, /grouplist 그룹 목록 화면, /groups/:groupId/votes 그룹별 투표 화면이 있습니다. 메인 화면의 카카오 버튼은 Kakao OAuth로 이동하고, 인증이 끝나면 그룹 목록으로 이동합니다.

메인 화면의 구성

  • 상단에는 FOOD TAROT 라벨이 있습니다.
  • 제목은 오늘 뭐 먹지?, 운명에게 물어봐. 두 줄입니다.
  • 부제목과 카카오 시작하기 버튼이 있습니다.
  • 캐릭터 이미지는 assets/images/mascots/landing-mascots.png에서 가져옵니다.
  • 별, 반짝임, 달 배경은 이미지가 아니라 대부분 CSS와 JSX 요소로 만듭니다.
중요한 상태: 카카오 로그인 플로우는 백엔드와 연결되어 있습니다. 프론트는 Kakao 인증 URL을 만들고, 콜백에서 받은 code를 VITE_API_BASE_URL의 POST /api/auth/kakao로 보냅니다. 응답으로 받은 토큰과 회원 정보는 localStorage의 unsik:auth_session에 저장합니다.

그룹 목록 화면의 구성

  • /grouplist에서 로그인한 사용자의 참여 그룹을 백엔드에서 조회합니다.
  • 방 만들기, 초대코드 참여, 초대 링크 복사, 방 삭제가 API 기준으로 동작합니다.
  • /grouplist?code=... 초대 링크는 로그인 전이면 잠시 저장했다가 로그인 후 자동 참여합니다.
  • 방 우상단 메뉴에서 링크 복사와 방 삭제를 실행할 수 있습니다.
  • 메뉴는 메뉴 버튼, 바깥 클릭, Esc 키로 닫힙니다.
  • 로그인 전, 로딩 중, 빈 목록, API 실패 상태를 화면에서 구분합니다.

투표 화면의 구성

  • 방에 들어가면 /groups/:groupId/votes에서 투표 목록과 새 투표 만들기를 보여줍니다.
  • 새 투표는 위치, 참여자, 선호 cuisine, 알레르기/제한 정보를 거쳐 추천 후보를 받습니다.
  • 후보 카드에서 좋아/별로를 고른 뒤 최종 확정 단계에서 투표 결과를 백엔드에 제출합니다.
  • 최종 메뉴가 정해지면 GET /api/restaurants로 주변 식당을 조회하고 카카오맵 링크를 엽니다.
  • 그룹별 투표 목록 조회 API가 없어 새로고침 후 영구 투표 목록은 아직 불러오지 않습니다.

PWA 기본 구성

  • index.html은 /manifest.webmanifest를 연결합니다.
  • src/pwa.ts는 프로덕션에서만 /service-worker.js를 등록합니다.
  • 서비스 워커는 앱 셸과 정적 파일만 캐시하고 /api/* 요청은 캐시하지 않습니다.

2. Spring Boot 관점으로 보면

백엔드 개발자가 처음 헷갈리는 지점은 “서버가 HTML을 만들어 주는가?”입니다. 이 프로젝트에서는 서버가 화면 HTML을 매번 렌더링하지 않습니다. 브라우저가 JavaScript 번들을 받고, React가 사용자의 브라우저 안에서 DOM을 만듭니다.

Spring Boot에서 익숙한 개념 React 프론트에서 대응되는 개념 이 프로젝트에서의 위치
Controller 메서드 사용자 요청을 받아 화면이나 JSON을 반환 src/services/auth.ts와 src/services/backend.ts가 백엔드 API를 호출합니다. 화면 컴포넌트는 서비스 함수만 사용합니다.
Thymeleaf/JSP 템플릿 React 컴포넌트가 JSX로 화면 구조를 표현 src/components/main, src/components/rooms, src/components/votes
DTO API 응답 타입, 컴포넌트 props 타입 GroupResponse, VoteResponse, RestaurantDocument 같은 타입이 backend.ts에 있습니다.
application.yml .env의 VITE_* 환경변수 VITE_API_BASE_URL 같은 공개 값만 사용합니다.
Gradle/Maven build Vite build npm.cmd run build가 타입 검사 후 번들을 만듭니다.
주의: React 클라이언트 코드는 최종적으로 사용자의 브라우저에 내려갑니다. 그래서 DB 비밀번호, JWT 서명키, 외부 API secret 같은 값은 절대 프론트 코드나 VITE_ 환경변수에 넣으면 안 됩니다.

3. 화면이 뜨는 흐름

프론트 코드를 읽을 때는 “어떤 파일부터 실행되는가?”를 먼저 잡으면 됩니다. 현재 앱의 실행 흐름은 아래 순서입니다.

1
index.html

브라우저가 처음 받는 HTML입니다. 여기에는 React가 붙을 빈 DOM인 <div id="root"></div>가 있습니다.

2
src/main.tsx

document.getElementById('root')로 DOM을 찾고, createRoot(root).render(...)로 React 앱을 붙입니다. 마지막에 registerServiceWorker()도 호출합니다.

3
src/App.tsx

앱의 최상단 컴포넌트입니다. 지금은 window.history 기반으로 /main, /auth/kakao/callback, /grouplist, /groups/:groupId/votes URL을 관리하고 알맞은 화면 컴포넌트를 렌더링합니다.

4
화면 컴포넌트

메인은 src/components/main, 카카오 콜백은 src/components/auth, 방 목록은 src/components/rooms, 투표 흐름은 src/components/votes가 담당합니다.

5
src/services/auth.ts

카카오 로그인 URL 생성, OAuth state 검증, POST /api/auth/kakao 호출, 인증 세션 저장을 담당합니다.

6
src/services/backend.ts

그룹, 멤버, 메뉴, 투표, 식당 API 호출과 응답 파싱을 담당합니다. 컴포넌트는 이 파일의 의도 중심 함수만 호출합니다.

7
화면별 CSS와 에셋

각 화면 폴더의 CSS가 배치와 상태 스타일을 담당하고, 캐릭터 이미지는 assets/images/mascots에서 import합니다. 

index.html
  -> src/main.tsx
    -> src/pwa.ts
    -> src/App.tsx
      -> src/components/main/main-screen.tsx
      -> src/components/auth/kakao-callback-screen.tsx
      -> src/components/rooms/room-list-screen.tsx
      -> src/components/votes/vote-flow-screen.tsx
      -> src/services/auth.ts
      -> src/services/backend.ts
      -> assets/images/mascots/landing-mascots.png

4. 파일별 역할

프론트 프로젝트에서는 파일이 많아지기 쉽습니다. 처음에는 “진입점, 화면, 스타일, 에셋, 설정”으로 나눠서 보면 됩니다.

src/main.tsx React 앱을 브라우저 DOM에 붙이는 시작점입니다. 일반적으로 자주 수정하지 않습니다.
src/App.tsx 전체 앱 구성을 잡는 파일입니다. 별도 라우터 없이 /main, /auth/kakao/callback, /grouplist, /groups/:groupId/votes URL 전환을 처리합니다.
src/pwa.ts 프로덕션 빌드에서만 서비스 워커를 등록합니다. 개발 중에는 캐시 문제를 피하려고 등록하지 않습니다.
src/styles.css 전역 CSS입니다. body 기본 배경, 폰트, box-sizing, root 높이 같은 공통 기준을 둡니다.
src/components/main/main-screen.tsx 메인 화면의 JSX 구조와 화면 문구를 담고 있습니다.
src/components/main/main-screen.css 메인 화면 전용 CSS입니다. 위치, 크기, 색상, 모바일 대응, 애니메이션을 담당합니다.
src/components/auth/kakao-callback-screen.tsx 카카오가 돌려준 code와 state를 확인하고 백엔드 인증 요청을 시작하는 콜백 화면입니다.
src/services/auth.ts 카카오 로그인 URL 생성, OAuth state 검증, POST /api/auth/kakao 호출, 인증 세션 저장을 담당합니다.
src/services/backend.ts 그룹, 메뉴, 투표, 식당 API 호출과 응답 파싱을 담당합니다. API 경로가 바뀌면 먼저 이 파일을 봅니다.
src/components/rooms/room-list-screen.tsx 그룹 목록 화면입니다. API 기반 방 목록, 방 만들기, 초대코드 참여, 링크 복사, 삭제, 메뉴 열고 닫기 상태를 관리합니다.
src/components/rooms/room-list-screen.css 그룹 목록 화면 전용 CSS입니다. 방 카드, 드롭다운 메뉴, 모달, 토스트, 빈 상태를 담당합니다.
src/components/votes/vote-flow-screen.tsx 그룹별 투표 목록, 투표 생성, 선호 입력, 추천 후보, 호불호 투표, 최종 메뉴, 식당 상세 화면을 관리합니다.
src/components/votes/vote-flow-screen.css 투표 흐름 화면 전용 CSS입니다. 카드, 단계별 화면, 식당 목록, 결과 상세 스타일을 담당합니다.
assets/ React 코드에서 import해서 쓰는 이미지 같은 원본 에셋을 둡니다.
public/ 브라우저 URL로 바로 접근되는 정적 파일을 둡니다. favicon, PWA 아이콘, manifest, service worker 같은 용도입니다.
vite.config.ts @/가 src/를, @/assets/가 assets/를 가리키도록 별칭을 잡습니다.

5. React 기본 개념

React는 “화면을 함수로 쪼개고, 데이터가 바뀌면 화면을 다시 계산하는 라이브러리”라고 보면 됩니다. 현재 코드는 메인 화면, 카카오 콜백, 그룹 목록, 투표 흐름과 API 상태를 가지고 있어서 컴포넌트, props, state, effect를 모두 확인할 수 있습니다.

컴포넌트

컴포넌트는 UI 조각을 반환하는 함수입니다. Java 메서드가 값을 반환하듯, React 컴포넌트는 JSX라는 화면 구조를 반환합니다. 

export function App() {
  const [route, setRoute] = useState<AppRoute>(() => getAppRoute(window.location.pathname));

  if (route.type === 'groups') {
    return <RoomListScreen onBack={() => navigate({ type: 'main' })} />;
  }

  if (route.type === 'groupVotes') {
    return <VoteFlowScreen groupId={route.groupId} onBackToRooms={() => navigate({ type: 'groups' })} />;
  }

  return <MainScreen onKakaoLogin={handleKakaoLogin} />;
}

JSX

JSX는 HTML처럼 보이지만 JavaScript 안에서 UI를 표현하는 문법입니다. HTML의 class 대신 className을 쓰고, JavaScript 값을 넣을 때는 중괄호 {}를 씁니다. 

<h1 id="main-title" className="main-title">
  {COPY.title}
</h1>

props

props는 부모 컴포넌트가 자식 컴포넌트에게 전달하는 입력값입니다. Java에서 생성자 파라미터나 메서드 파라미터처럼 생각하면 됩니다. 현재 MainScreen은 onKakaoLogin을 받고, RoomListScreen은 memberId, token, onOpenRoom을 받으며, VoteFlowScreen은 groupId와 로그인 컨텍스트를 받습니다.

state

state는 화면이 기억해야 하는 값입니다. 현재 App은 현재 URL route를, RoomListScreen은 방 목록, 열린 메뉴 id, 열린 모달, 토스트 메시지, 초대 링크 처리 상태를 state로 관리합니다. VoteFlowScreen은 현재 단계, 참여자, 선호 조건, 추천 후보, 최종 메뉴, 식당 목록을 state로 관리합니다. state가 바뀌면 React가 화면을 다시 렌더링합니다.

effect

effect는 렌더링 이후에 실행해야 하는 부수 작업입니다. 현재 App은 브라우저 뒤로가기 이벤트를 듣고, RoomListScreen은 메뉴 바깥 클릭과 Esc 키 입력, 그룹 목록 조회, 초대 링크 자동 참여, 토스트 타이머 정리를 effect로 처리합니다. VoteFlowScreen은 그룹원 조회, 메뉴 카탈로그 조회, 식당 검색을 effect로 처리합니다.

현재 코드에서 먼저 보면 되는 것: MainScreen은 첫 화면, KakaoCallbackScreen은 인증 완료 처리, RoomListScreen은 API 기반 그룹 목록, VoteFlowScreen은 투표 전체 흐름입니다. 작은 UI 조각은 각 화면 파일 아래의 하위 함수 컴포넌트로 나뉘어 있습니다.

6. TypeScript 기본 개념

TypeScript는 JavaScript에 타입 검사를 얹은 언어입니다. Java처럼 런타임에 타입이 강제되는 언어는 아니지만, 개발 중에 잘못된 필드명, 잘못된 함수 인자, null 가능성 같은 문제를 미리 잡아줍니다.

strict 모드

이 프로젝트는 TypeScript strict 모드입니다. 대충 any로 넘기기보다 데이터 모양을 명확히 작성해야 합니다. 서버 API와 연결할 때 특히 중요합니다.

as const

현재 COPY, STARS, SPARKLES 뒤에는 as const가 붙어 있습니다. 값이 실수로 바뀌지 않는 읽기 전용 상수라는 의도를 TypeScript에게 알려주는 표현입니다.

타입 체크

npm.cmd run typecheck는 코드를 실행하지 않고 타입 오류만 검사합니다. Java 프로젝트에서 컴파일 단계로 타입 오류를 잡는 것과 비슷하게 보면 됩니다.

7. CSS 읽는 법

React가 화면의 뼈대를 만들고, CSS가 그 뼈대를 배치하고 꾸밉니다. 현재 메인 화면, 그룹 목록 화면, 투표 화면은 CSS의 비중이 큽니다. 모바일 크기, 달 배경, 별 애니메이션, 방 카드, 메뉴 팝오버, 모달, 토스트, 투표 카드, 식당 목록 스타일이 모두 CSS에 있습니다.

클래스 연결

JSX의 className="main-title"은 CSS의 .main-title과 연결됩니다. 

.main-title {
  font-size: 40px;
  line-height: 52px;
  white-space: pre-line;
}

white-space: pre-line

COPY.title 안의 \n 줄바꿈을 실제 화면 줄바꿈으로 보여주기 위해 사용합니다. 이 속성이 없으면 문자열의 줄바꿈이 공백처럼 처리될 수 있습니다.

min-height: 100dvh

모바일 브라우저는 주소창이 접히고 펴지면서 화면 높이가 바뀝니다. dvh는 그런 동적 viewport 높이를 고려하는 단위입니다.

env(safe-area-inset-bottom)

아이폰처럼 홈 인디케이터가 있는 기기에서 버튼이 하단 시스템 UI에 너무 붙지 않도록 여백을 추가합니다.

반응형 CSS

@media는 조건부 CSS입니다. 현재 화면은 폭이 좁거나 높이가 낮을 때 제목 크기, 일러스트 높이, 버튼 영역 간격을 줄입니다.

팝오버와 stacking

방 메뉴는 카드 안에서 절대 배치되는 팝오버입니다. 열린 카드에는 room-card-open 클래스를 붙여 z-index를 올리고, 위쪽 카드의 메뉴가 아래 카드 뒤로 숨지 않게 합니다.

8. 이미지와 정적 파일

프론트에서는 이미지 파일을 어디에 두는지도 중요합니다. 이 프로젝트는 두 가지 위치를 구분합니다.

위치 용도 사용 방식
assets/ React 코드에서 import해서 번들에 포함할 이미지 import mascotImage from '@/assets/images/mascots/landing-mascots.png'
public/ favicon처럼 URL로 바로 제공할 정적 파일 /favicon.ico처럼 절대 경로로 접근
기준: 컴포넌트가 직접 쓰는 화면 이미지라면 보통 assets/가 맞고, 브라우저나 외부 서비스가 고정 URL로 찾아야 하는 파일은 public/이 맞습니다.

9. 백엔드 연결 상태와 다음 연결 지점

현재 앱은 카카오 인증, 그룹, 그룹 멤버, 메뉴 카탈로그, 투표 생성/추천/투표/마감/삭제, 식당 검색을 백엔드와 통신합니다. 인증은 src/services/auth.ts, 나머지 Swagger API는 src/services/backend.ts에 모아 두었습니다.

현재 연결된 주요 API

  1. POST /api/auth/kakao: 카카오 code를 토큰과 회원 정보로 교환합니다.
  2. GET/POST/DELETE /api/groups: 방 목록, 방 만들기, 방 삭제를 처리합니다.
  3. POST /api/groups/join: 초대코드나 초대 링크로 그룹에 참여합니다.
  4. GET /api/groups/{groupId}/members: 방 인원 수와 투표 참여자 후보를 가져옵니다.
  5. GET /api/menus: 오늘의 취향 화면에서 검색할 메뉴 카탈로그를 가져옵니다.
  6. POST /api/groups/{groupId}/votes: 투표 제목, 위치, 참여자를 보내 투표를 만듭니다.
  7. POST /api/votes/{voteId}/preferences와 /recommend: 선호 조건을 제출하고 추천 후보를 받습니다.
  8. POST /api/votes/{voteId}/ballots, /close, GET /api/votes/{voteId}: 후보 호불호와 최종 메뉴 확정을 처리합니다.
  9. DELETE /api/votes/{voteId}: 진행 중인 투표를 취소합니다.
  10. GET /api/restaurants: 확정 메뉴와 voteId 기준으로 카카오 로컬 식당 문서를 가져옵니다.

아직 백엔드 계약이 필요한 부분

  • 그룹별 투표 목록 조회 API가 없어 새로고침 후 DB에 저장된 투표 목록을 불러오지 못합니다.
  • 위치 투표 전용 API가 없어 화면 위치 선택은 투표 생성의 school 값으로만 전달합니다.
  • 메뉴 단위 제외 API가 없어 검색으로 제외한 메뉴는 해당 메뉴의 cuisine으로 변환해 제출합니다.
  • 식당 평점, 리뷰, 가격대, 영업 상태는 카카오 로컬 응답에 없어 표시하지 않습니다.
  • 실제 푸시 알림은 아직 없습니다. 현재는 브라우저 Notification API로 즉시 로컬 알림만 시도합니다.

환경변수

Vite에서 브라우저 코드로 노출되는 환경변수는 VITE_로 시작해야 합니다. 

VITE_API_BASE_URL=http://localhost:3000
VITE_KAKAO_REST_API_KEY=카카오 REST API 키
VITE_KAKAO_REDIRECT_URI=http://localhost:5173/auth/kakao/callback
다시 강조: VITE_ 값은 브라우저 번들에 들어갑니다. 공개되어도 되는 API base URL 정도만 넣고, secret은 백엔드에서만 관리해야 합니다.

10. 용어 사전

처음에는 용어가 제일 피곤합니다. 아래 개념을 먼저 잡으면 현재 프로젝트를 읽는 데 충분합니다.

SPA

Single Page Application. 처음 받은 HTML 하나 위에서 JavaScript가 화면을 바꿔 가며 동작하는 앱입니다.

DOM

브라우저가 HTML을 객체 트리로 표현한 것입니다. React는 이 DOM을 효율적으로 갱신합니다.

번들

여러 TS, CSS, 이미지 import를 브라우저가 읽을 수 있는 파일 묶음으로 만든 결과입니다.

Vite

개발 서버와 빌드를 담당하는 도구입니다. 빠른 HMR과 번들 생성을 제공합니다.

HMR

Hot Module Replacement. 저장하면 브라우저 전체 새로고침 없이 바뀐 부분을 빠르게 반영하는 기능입니다.

컴포넌트

화면 조각을 반환하는 함수입니다. 작게 나눌수록 읽고 테스트하기 쉬워집니다.

JSX

JavaScript 안에서 HTML 비슷한 문법으로 UI 구조를 쓰는 방식입니다.

props

부모가 자식 컴포넌트에 넘기는 입력값입니다. 컴포넌트의 파라미터라고 보면 됩니다.

state

화면이 기억하는 값입니다. 값이 바뀌면 React가 화면을 다시 계산합니다.

effect

렌더링 이후에 필요한 외부 작업입니다. API 호출, 타이머, 이벤트 구독 같은 것이 여기에 해당합니다.

반응형

폰, 태블릿, 데스크톱처럼 화면 크기가 달라도 깨지지 않게 만드는 방식입니다.

접근성

키보드, 스크린리더, 저시력 사용자도 기능을 쓸 수 있도록 만드는 기준입니다.

11. 개발 루틴

프론트는 화면으로 바로 확인할 수 있어서 감으로 고치기 쉽지만, 최소한의 루틴을 지켜야 나중에 덜 고생합니다.

1. 실행

npm.cmd run dev로 개발 서버를 켭니다. PowerShell 정책 때문에 npm 대신 npm.cmd를 씁니다.

2. 수정

문구와 구조는 .tsx, 크기와 배치는 .css, 이미지 교체는 assets/를 봅니다.

3. 검증

TypeScript를 바꿨으면 npm.cmd run typecheck, 큰 변경이면 npm.cmd run check까지 실행합니다.

자주 쓰는 명령어

명령어 의미
npm.cmd install 의존성을 설치합니다.
npm.cmd run dev 개발 서버를 실행합니다.
npm.cmd run typecheck TypeScript 타입 오류를 검사합니다.
npm.cmd run lint 코드 스타일과 잠재 오류를 검사합니다.
npm.cmd run build 배포 가능한 정적 파일을 만듭니다.
npm.cmd run check 타입 검사, lint, build를 한 번에 실행합니다.

12. 추천 공부 순서

지금 프로젝트를 기반으로 공부한다면 아래 순서가 가장 현실적입니다. 책처럼 처음부터 끝까지 보기보다, 화면을 직접 바꿔 보면서 익히는 편이 빠릅니다.

  1. HTML과 DOM: index.html의 root가 왜 필요한지 이해합니다.
  2. JSX: MainScreen의 태그 구조를 HTML처럼 읽어 봅니다.
  3. CSS: .main-title, .main-kakao-login-button, @media를 바꿔 보며 화면 변화를 확인합니다.
  4. 라우팅: App.tsx에서 URL을 읽고 어떤 화면을 렌더링하는지 따라갑니다.
  5. TypeScript: backend.ts의 응답 타입과 파서가 화면을 어떻게 보호하는지 봅니다.
  6. React state: RoomListScreen과 VoteFlowScreen에서 loading, empty, error, success 상태가 어떻게 나뉘는지 읽습니다.
  7. API 연결: 카카오 인증 흐름을 먼저 읽고, 그 다음 그룹 API, 투표 API, 식당 API 순서로 따라갑니다.
  8. PWA: src/pwa.ts, public/manifest.webmanifest, public/service-worker.js가 각각 무엇을 맡는지 확인합니다.
작업 기준: 새 화면을 만들 때는 먼저 모바일에서 정보 구조가 자연스러운지 보고, 그 다음 데스크톱 폭에서 너무 늘어나거나 깨지지 않는지 확인합니다.
문서 기준: 현재 unsik-fe React 웹 랜딩 화면. 이 파일은 브라우저에서 바로 열어 볼 수 있는 다크 모드 학습 문서입니다.
